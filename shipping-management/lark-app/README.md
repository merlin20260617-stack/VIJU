# VIJU 成品仓发货管理

## 需求背景
供成品仓每天录入订单，按现场实际发货情况确认已发，并统一汇总客户订单、产品出货及库存。应用与业务数据均部署在Lark；GitHub仅保存源码。用户当前为Lark基础版测试阶段，后续计划升级Pro；不得引入额外付费服务而未事先说明并取得确认。

## 用户希望的功能
每页100客户位置；客户产品逐条维护与Excel导入；实际发货后确认、撤回修改；工厂仓库管理；24小时生产待入库；客户、订单、产品与仓库汇总。

## 站点已提供的能力
真实Lark应用、可信角色查询、按仓库隔离的查询与服务端业务写入。工作台每页10×10客户位置，支持订单产品、箱数、整板、余箱标红；装货后转已完成，撤回恢复待装货。支持多产品订单、装货顺序、主数据逐条维护及.xlsx/CSV导入、生产24小时待入库、库存和汇总CSV导出。

订单与产品明细快照以Orders.LinesJson为准；应用报表从订单主台账计算，旧OrderLines表仅为前一测试版的历史投影，不再作为当前报表来源。操作回执与审计保存在Lark的SyncReceipts；字段TransactionVersion在本版存放仓库范围，Details保存已验证写入计划和操作记录。无Sites/Cloudflare运行时依赖，不读取原事务服务凭据。

## 当前状态与边界
本版本为Preview。用户已接受每仓一名仓管依次确认实际已发，不承诺多人同时确认同仓订单时的事务保证。不同仓库独立核算；管理员查看全部，Warehouse/Viewer角色目前每人配置一个准确的仓库代码，未配置或重复角色拒绝访问。权限由服务端和每个SQL固定查询校验，页面不能自选身份。

Base不提供事务、唯一键或条件更新。写前校验库存、状态与快照变化；重复点击在页面阻止。写入未知或部分完成时保留回执并暂停相关仓库新操作，核查入口只确认全部匹配的结果，不重放业务写入。不能把上述保护称作严格幂等或事务锁。直接修改底表可能造成回执不匹配，应通过平台维护，异常需管理员核对。

Excel先完整校验，最多10MB/5000行；确认后每50行依次保存，基础版容量及平台接口额度仍适用。批次间无事务；中途失败保留已保存批次，不承诺整文件回滚。旧.xls先另存.xlsx，公式先粘贴为值。单次订单最多100种产品、确认最多200单。各表超过10000条时拒绝截断读取并要求优化查询，不代表基础版支持该容量。

保存后页面立即更新，后台约30秒刷新；查询暂未追上写入时保留上次显示并暂停下一次写入。库存计算为期初+满24小时生产−当前已完成数量，未满24小时单列待入库。基础版额度及未来Pro能力需以实际账号为准，不自动购买或升级。真实ERP文件、普通员工账号及手机端仍待验收。

客户与产品支持下载真正的.xlsx导入模板：第一工作表为空白导入表，表头与导入字段一致，代码列预设文本；第二工作表说明填写方法。模板作为应用静态制品保存在Lark，通过宿主打开下载，不依赖浏览器blob链接或外部服务。
基础资料支持逐条删除、勾选及全选批量删除，每次最多200条；仅管理员可操作。删除前列出代码和名称供确认；任何一条资料已被订单、生产、期初或仓库资料引用时，整批在写入前拒绝。Base批量写入仍不提供事务，执行结果未知或部分完成时按回执暂停并核对，不自动重试。Excel模板下载使用同源静态xlsx文件的原生下载链接。
