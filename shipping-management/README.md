# VIJU 成品仓发货管理

独立项目：`merlin20260617-stack/VIJU/shipping-management/`。

## 需求背景
供成品仓每天录入销售订单、按装货顺序装车、统一查看客户订单和产品库存汇总。

## 用户希望的功能
每页10×10客户位置；客户/产品逐条新增修改及Excel批量导入；装货完成与撤回；工厂仓库管理；carton与每板标准；生产完成24小时后可发库存；统一出货、待发、客户、产品和库存报表。

## 站点已提供的能力
真实Lark应用、11张业务表、可信账号角色查询已建立；经用户明确批准，私有D1事务服务负责权威库存，Lark保存同步台账。

- [Lark Preview](https://qjpb2ivmka4y.jp.larksuite.com/baseapp/IJvUpRVOmrzZu1jRqiRjN8zYpye?mode=edit)；正式版尚未发布。
- `lark-app/`：官方SDK workspace，真实工作台、Database Function、FaaS桥接与实际Catalog。
- `transaction-service/`：私有Sites/D1服务，原子版本更新、业务实体、审计、请求回执和耐久同步队列。必须保持owner-private，不得直接扩大访问范围。
- `domain/`、`tests/`：仓库业务规则、Excel/CSV校验和事务测试。
- `page/`、`server/preview.mjs`：明确标识本地模式的旧演示，用于隔离功能试验，不是真实Lark入口。

工作台每页100位置，按当天订单分配，完成后原位置留空；支持更多客户分页。产品分别按下单时板载标准计算整板、余箱、板位，余箱标红。支持多产品订单、顺序、完成与撤回原因。

主数据支持.xlsx和UTF-8 CSV，工作表选择、字段匹配、错误预览、重复代码报错/跳过/更新及前导零保留；最多10MB/5000行，服务请求另受1MB限制，大文件需分批；旧.xls请另存为.xlsx，公式需粘贴为值。提供CSV模板，可用Excel另存为xlsx。

可发库存=期初+满24小时生产量−当前已完成数量；未满24小时单列待入库。总订单/待装货按订单日期，当日已发按实际完成日期。报表支持日期范围、工厂、仓库、客户、产品筛选和CSV导出。

## 验证
26项业务与SQLite事务测试通过。真实Lark Preview已验证管理员身份、真实订单/生产/期初写入、装货1000→720箱、撤回恢复1000箱，未成熟500箱隔离，Lark台账回读与同步队列完成。线上两个订单争用库存时一笔成功，一笔收到版本冲突，未超发；验收后已恢复库存。界面已实际显示两张示例订单与410箱汇总。详见`implementation/live-verification.md`。

## 当前状态与边界
- 当前为Preview，只有已授权管理者可体验；正式版尚未提升。普通员工、多角色及手机端真实验收未完成。
- 已存在明确“示例”标记的测试资料、订单及生产批次，均非ERP真实数据。
- .xlsx解析、工作表、前导零及导入校验已在隔离浏览器验证；真实Lark宿主的文件选择自动化未完成，用户ERP样本需做试导。不能把本地解析测试当成真实ERP导入端到端验收。
- Lark调用曾出现临时返回异常；已使用耐久回执及只读队列核对确认保存，未重复业务写入。未知结果保留操作编号，管理员核查后处理；同步不确定时停止盲目重写。
- 快照查询当前上限20,000条业务/审计实体，达到上限时拒绝继续，需要升级分区与分页查询。
- 暂不包含部分发货、退货、盘点调整、生产批次更正或历史库存快照。
- Lark服务端Secret不进入页面或Git；配置值与生产发布授权独立管理。Prod需体验并确认同一Preview制品后发布。

## 开发

Node.js 22.13+。根目录`npm test`运行26项测试，`npm run preview`仅启动隔离本地演示。真实工程在`lark-app/`，使用Lark Base Database CLI及原账号profile检查、部署；所有表ID以Catalog为准，不能复用其他VIJU应用凭据。CLI1.6.0的隔离codegen在Node24需兼容使用--permission，建议维护时使用受支持Node22工具链；本次保留全部隔离与验证。
