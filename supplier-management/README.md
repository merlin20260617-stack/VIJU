# VIJU 供应商管理平台

独立的新项目。GitHub 保存源码，应用、函数和业务数据全部运行于 Lark。需求依据：VIJU_Nigeria_Local_Supplier_Management_Project_CN.pdf，V1.0 讨论稿，3页。

## 需求背景

三张核心表分别管理供应商、仓库权威物料主档及供应商与物料的多对多关系。Members 仅用于应用内职责校验，由管理员在底表维护，不提供页面自助提权接口。

供应商产品型号不能替代 VIJU 物料编码。供货核实与技术适配分别记录；实际采购过不能自动证明替代件或设备适配。附件保存在 Base 附件字段。

不建设订单、库存、价格或付款模块，不开发 ERP 接口，不导入财务交易明细和银行账户。

## 用户希望的功能

- 供应查询：按物料编码、名称、供应商、设备、工厂及验证状态检索，显示联系人和产品资料。
- 供应商：档案维护、资料待补充、合作评价与依据。
- 物料主档：中央仓维护，保留已有物料编码与前导零。
- 供货关系：采购核实供货，技术人员独立确认适配。
- 数据质量：缺失信息、待核实及待技术确认队列。
- 导入：先预览和查重，再受控新增/更新；不整库覆盖，不导入附件空值覆盖照片。

## 站点已提供的能力

已实现供应查询、供应商与物料档案维护、供货关系与技术确认、待核实队列、Excel/CSV导入预览和新增/更新分批提交、Excel模板下载、附件追加与展示入口。附件实际能力以目标环境验收为准。

平台面向集团内部采购、仓库、技术及获授权查询人员。查询业务资料共享；采购维护供应商与供货信息，中央仓维护正式物料，技术维护适配结论，管理员可处理全部业务。成员权限来源禁止通过业务函数修改；所有角色敏感写入必须在服务端以 CURRENT_USER_ID() 核验。

## 验收路径

1. 录入供应商及由中央仓确认的物料编码，建立对应关系。
2. 输入物料编码，查到供应商、联系人、供货状态与产品资料。
3. 采购将供货状态改为已核实，技术状态仍保持待确认。
4. 技术人员记录有依据的适配结论。无该角色的调用必须拒绝。
5. 对同一物料做字段受控更新，照片、供应关系、评价和联系人保持不变。
6. 同名供应商/重复物料编码/重复关系拒绝或进入人工合并流程。

## 平台限制

Base 不提供已验证的唯一约束、事务和原子条件更新。写前查重不能承诺严格并发唯一性；试点由指定数据维护人员依次处理新增和导入，定期检查重复项。创建结果未知时停止重提，核对记录后人工处理。

试点以奥贡为首期；范围、真实负责人、数量及时间由采购部评估后确定。附件未提供实际 Item Master 和供应商名录，不能据此虚构真实业务数据。
