# VIJU 集团供应商管理平台

## 需求背景

为集团跨国家、跨工厂长期积累供应商资料、物料供货经验、技术适配结论、资质与合作评价。平台面向全球供应商，首期以少量试点资料验证流程。GitHub保存独立项目源码，应用、业务函数和数据运行于Lark。

需求依据包括用户提供的VIJU供应商管理项目讨论稿及后续明确的全球化、管理后台、ERP导入、角色权限、看板报表和长期治理要求。功能参考SAP Ariba供应商生命周期/绩效/风险及Oracle供应商资质管理的公开官方资料，按VIJU现有ERP和工厂职责落地。

## 用户希望的功能

- 用户端操作简单：搜索供应商、物料和设备，查看供货与技术核实状态，提交评价或问题，查看授权报表。
- 管理端完整：全球供应商主数据、ERP字段映射和预览导入、批量选择/修改/保护性删除、准入分级、资质审核、绩效和整改闭环、操作记录及角色/成员管理。
- 角色分别控制菜单模块、数据查询、看板/报表和写操作；不以隐藏按钮代替服务端权限。
- 当前从鼎捷ERP手动导出整理后导入，未来评估接口对接。

## 站点已提供的能力

### 业务数据与流程

九张表：Suppliers、Materials、SupplyMappings、Members、Roles、SupplierQualifications、SupplierEvaluations、SupplierIssues、ActivityLog。正式物料编码沿用仓库/ERP权威主档；供应商产品型号独立记录。供应商按国家、试点/正式阶段、生命周期、合作等级、风险分级管理，供货验证与技术适配分别确认。

资质支持审核依据、有效期或长期有效及附件。合格准入要求有评审依据、至少一项审核通过且有效的资质，并阻止未关闭的高风险问题通过准入；该通用试点规则不代表各国家完整合规要求。绩效按质量、交付、服务、协同记录0–100分，权重由每份评价明确填写且必须合计100%，综合分在服务端计算。评价保留历史，不覆盖旧记录。问题有责任人、工厂、整改措施、截止日期和关闭依据。

### 管理后台与鼎捷ERP准备

支持Excel/XLS/CSV、多工作表和表头行选择、中文/英文常见字段自动建议及人工映射。供应商编号与ERP供应商编码、物料编码与ERP物料编码及来源系统分别保留。可按平台编号或“来源系统＋ERP编码”匹配；ERP更新保留原平台编号，首次新增仍须提供平台编号。每文件最多2000条，先全文件校验，再以100条为一批依次提交，出错或未知结果即停止；显示已完成数量，不自动重提。新增和更新分开，空值跳过，附件、生命周期、风险及技术结论不属于ERP导入覆盖字段。

支持跨页面勾选、当前页全选、选择筛选结果（最多200条）、批量修改及删除预览。批量更新只写勾选字段，不改编号和名称；删除前逐条检查供货、资质、绩效及整改关联，有任一被引用即拦截整批，并要求输入确认文字。建议停用而非删除有历史的供应商。

### 角色与数据访问

默认提供管理员、采购、中央仓、技术、只读五个可配置角色；可新增角色，配置供应商/物料/供货关系、技术确认、资质、绩效、整改、准入、批量管理、ERP导入、角色管理、日志及看板报表权限，再分配给成员。服务端通过CURRENT_USER_ID()查本人有效成员与启用角色。所有明细查询在SQL中实施权限过滤，只有看板权限者通过汇总函数取得聚合数据，不能调用明细函数越权查看。报表权限包含共享主数据的明细及导出。

成员与角色写入单独受权限管理能力约束。不能修改本人成员权限，不能停用本人当前角色或移除其角色管理权限。初始管理员保留原系统角色作为引导入口。当前授权粒度为模块和操作，国家/工厂筛选为查询条件，尚未实现按国家或工厂的行级数据隔离；底表直接访问权限需由Base所有者管理。

### 看板、报表及操作记录

看板显示集团物料总数、筛选供应商/供货关系、待技术确认、高风险供应商，按国家、生命周期、供货验证、适配状态汇总。国家、阶段与工厂筛选按指标口径作用。报表包含供货明细、物料覆盖、供应商总览、待核实、资质到期、整改和绩效，支持当前筛选结果Excel导出。

业务写入先登记操作编号与操作者，后记录业务回执与完成状态，角色授权、导入和批量操作同样留痕。日志记录作用对象、影响ID、字段摘要、结果和时间；无业务接口可修改任意历史日志。日志与业务写入不是事务，未知或部分结果会保留待核查，不伪装全部完成。

## 当前状态与边界

集团版源码已完成首轮整合，36项业务规则测试通过；官方查询、构建及真实Preview验收按本次交付结果记录，不能将旧版Preview验收代替新版。真实ERP文件、附件和其他真实角色账号仍需试点验收。当前只发布Preview，正式发布需用户体验同一制品后明确授权。

Base没有已验证的唯一约束、事务或原子条件更新。写前查重、预览变更检查和本页串行操作降低误操作，不能保证多个用户并发时的严格唯一性或删除引用原子保护。新增、导入及批量维护由指定数据维护人员依次处理。当前每张台账读取上限为10000条，超过时明确停止，后续大规模推广需扩展服务端分页和按范围查询。看板日期按Africa/Lagos解释，跨国精细时区可后续配置。

鼎捷对接尚未开发或连接。未来需确认具体产品、版本、接口许可、业务主键、增量更新时间、数据归属和冲突策略，再在现有字段映射及校验层前增加适配器。当前不开发ERP实时接口、订单、库存、价格、付款、银行账户、供应商外部自助门户或外部风险数据订阅，未引入额外收费服务。
